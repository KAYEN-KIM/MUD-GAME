**What was generated:**

- **18 quests** (2 per season × 9 seasons): WB01 (Weekly Bonus) + ELITE_01

**Key Features:**
- ✅ **Idempotent:** Safe to rerun without duplicating data
- ✅ **Validated:** Built-in integrity checks (ID uniqueness, item references)
- ✅ **Automated:** One command to generate all S02-S10 content
- ✅ **Config-driven:** Easy to customize rewards/themes via JSON

## 🔧 Implementation Details

### 1. Config File: `tools/bonusweek_config.json`

**Purpose:** Single source of truth for season parameters

**Format:**
```json
{
  "seasons": [
    {
      "n": 2,
      "theme": "연무의 도서",
      "zoneId": "R1",
      "wbKill": 60,
      "eliteKill": 200,
      "wbGold": 800,
      "wbExp": 550,
      "eliteGold": 500,
      "eliteExp": 500
    },
    ...
  ],
  "defaults": {
    "potionItemId": "ITEM_POTION_HP_S",
    "potionQty": 5
  }
}
```

**Customization:**
- Edit `theme` for different season names
- Adjust `wbKill`/`eliteKill` for difficulty
- Change `wbGold`/`wbExp` for reward tuning
- Update `zoneId` when new zones are added (currently R1 for all)

---

### 2. Generator Script: `tools/generate_bonusweek_datapack.js`

**Features:**
- Reads config + existing content files
- Generates items + quests per season
- **Idempotent merge:** Checks existing IDs before adding
- Sorts output by ID (stable diffs)
- Saves to original file paths

**Generated per season (N = 02..10):**

#### Items (2 per season)
1. **`ITEM_ICON_BONUS_SNN`**
   - Name: "보너스 아이콘(SNN): {theme}"
   - Type: material, rarity: epic
   - sellGold: 0, stackMax: 1

2. **`ITEM_TITLE_BONUS_SNN`**
   - Name: "칭호(SNN): {theme} 러너"
   - Type: material, rarity: epic
   - sellGold: 0, stackMax: 1

#### Quests (2 per season)
1. **`Q_SNN_WB01`** (Weekly Bonus)
   - Title: "[WB] 보너스 주간: {theme}"
   - Objectives: KILL_IN_ZONE (zoneId=R1, count=60)
   - Rewards: gold=800, exp=550, ITEM_POTION_HP_S×5, ITEM_ICON_BONUS_SNN×1
   - **No seals** (인장 없음)
   - repeatable: false

2. **`Q_SNN_ELITE_01`** (Elite Challenge)
   - Title: "[ELITE] 보너스 주간: {theme}"
   - Objectives: KILL_IN_ZONE (zoneId=R1, count=200)
   - Rewards: gold=500, exp=500, ITEM_TITLE_BONUS_SNN×1
   - **No seals** (인장 없음)
   - repeatable: false

**Usage:**
```bash
# First run (generates all)
pnpm content:gen:bonusweek
# Output: Items: 18 added, 0 skipped | Quests: 18 added, 0 skipped

# Second run (idempotent)
pnpm content:gen:bonusweek
# Output: Items: 0 added, 18 skipped | Quests: 0 added, 18 skipped
```

### 3. Validation Script: `tools/validate_content.js`

**Checks:**
1. **Items ID uniqueness:** No duplicate item IDs
2. **Quests ID uniqueness:** No duplicate quest IDs
3. **Quest item references:** All reward itemIds exist in items.json

**Usage:**
```bash
pnpm content:validate
# Exit code 0 = PASS, 1 = FAIL
```

## 🚀 Operational Workflow

### For Season Content Updates

1. **Edit config (optional):**
```bash
# Edit tools/bonusweek_config.json
# Adjust rewards, themes, kill counts, etc.
```

2. **Generate content:**
```bash
pnpm content:gen:bonusweek
```

3. **Validate integrity:**
```bash
pnpm content:validate
```

4. **Sync catalog:**
```bash
pnpm catalog:sync
```

5. **Test:**
```bash
pnpm smoke
```

6. **Commit:**
```bash
git add apps/server/src/content/items.json
```

```bash
pnpm content:gen:bonusweek && pnpm content:validate && pnpm catalog:sync && pnpm smoke
```

## 🎓 Lessons Learned

1. **Idempotency is critical:** Developers will rerun generators (intentionally or accidentally) - must be safe
2. **Validation first:** Detect errors at generation time, not runtime
3. **Config over code:** Parameters in JSON = easier for non-developers to update
4. **Stable diffs:** Sorting output makes PR reviews cleaner
5. **Log verbosity:** Detailed logs (added/skipped counts) build developer confidence
